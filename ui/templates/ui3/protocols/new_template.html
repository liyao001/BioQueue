The example command is the echo line in the process_sample block, under Reusable blocks. Replace it with your software and arguments.

  • Name is required. Description is optional.
  • Files per sample starts at 1, which means one input file per sample. Use 2 for paired reads. The name pattern and extra fields are optional.
  • Reusable blocks are optional named lists of commands. The pipeline can hold those commands directly instead.
  • Pipeline is the run order. Add command (runs once) adds a command that runs a single time. Add for each sample repeats its commands for every sample. Put a command that needs every sample after that.
  • Commands. Software is required. Parameters, outputs, environment, version check, local run, and GPU are optional.

{% verbatim %}Inside for each sample, {{sample.r1}} is that sample's first file and {{sample.prefix}} is {{JobName}}_ plus the sample name. After it, {{samples.prefix}} lists every sample. An output name you choose, such as clean, is stored on the sample when the command runs for each sample ({{sample.clean}}), and once for the job when the command runs after that ({{shared.clean}}). A block stores its outputs the same way as the place it is called from.{% endverbatim %}
