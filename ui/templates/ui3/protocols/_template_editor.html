How later steps use an output Names for files a command writes
{% verbatim %}

An output row names a file the command writes. The value is that path, for example {{sample.prefix}}.fq.gz. BioQueue does not scan the results folder for new files. A later command uses the name instead of typing the path again.

Each sample already has index, name, prefix, r1, r2, and files. An output adds another name on top of those.

Inside a sample map, or in a block called from that map, the name is stored on the sample that is running.

  • The next command for that same sample uses {{sample.clean}}.
  • A command after the map uses {{samples.clean}} for every sample, separated by spaces.
  • {{samples.first.clean}} is the first sample, {{samples.last.clean}} is the last, and {{samples.2.clean}} is sample 2.

After the map, or in a block called from there, the name is shared by the whole job. A later command uses {{shared.merged_bam}}.

Example. Inside the map, a trim command writes {{sample.prefix}}.fq.gz and records the output name clean. The align command for that sample reads {{sample.clean}}. After every sample is done, a merge command reads {{samples.clean}} and records merged_bam. The report command reads {{shared.merged_bam}}.

A block argument is not an output. On the call, a row bam = {{sample.dedup_bam}} is read inside the block as {{bam}}. The value is filled in at the call, before the block starts.

Saving rejects a placeholder that is one edit away from a name you already declared, such as {{sample.clen}} when the output is clean. A new name such as {{sample.condition}} is kept, and the job asks for it under Samples.

{% endverbatim %}
